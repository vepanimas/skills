# Modifiers

Add an expression only when the situation calls for it. Put it in its own sentence and keep the expression's words. These expressions can be combined with any of the formats above.

| Expression | What it adds |
| --- | --- |
| **First principles** | Explains the topic starting from its most fundamental assumptions and principles. |
| **Conceptual framework** | Organizes individual ideas into a coherent system. |
| **Mental models** | Provides ways of thinking about and reasoning through problems. |
| **Intuition-first explanation** | Builds intuitive understanding before introducing technical details. |
| **Worked examples** | Demonstrates concepts through fully explained examples. |
| **Actionable takeaways** | Extracts practical lessons that can be applied immediately. |
| **Rules of thumb** | Provides useful heuristics and practical guidelines. |
| **Decision framework** | Helps choose between approaches based on context and constraints. |
| **Common pitfalls** | Highlights frequent mistakes, misconceptions, and failure modes. |
| **Progressive disclosure** | Introduces concepts gradually, moving from simple explanations to more advanced details. |
| **Self-contained** | Ensures the material can be understood without consulting additional resources. |

A few additional expressions are especially useful for more advanced learning:

| Expression | What it adds |
| --- | --- |
| **Trade-off analysis** | Explains what you gain and sacrifice when choosing between alternatives. |
| **Counterexamples** | Shows situations where a principle or technique does not apply. |
| **Boundary conditions** | Explains the circumstances under which an approach stops being effective. |
| **Critical appraisal** | Evaluates the strengths, weaknesses, assumptions, and evidence behind a theory. |
| **Synthesis** | Combines ideas from multiple sources into a coherent understanding. |
| **Taxonomy** | Organizes concepts into categories and shows how they relate. |
| **Knowledge map** | Provides a structured view of the subject and its interconnected concepts. |
| **Learning roadmap** | Organizes topics into a logical learning sequence. |

## Teaching style

You can also explicitly control the teaching style:

- **"Teach for understanding, not memorization."** Focuses on why concepts work.
- **"Optimize for practical fluency rather than academic completeness."** Prioritizes being able to use the material.
- **"Explain not just how, but when and why."** Adds decision-making context.
- **"Use contrasting examples to clarify subtle differences."** Helps distinguish similar concepts.
- **"Separate established theory, practitioner conventions, and your own recommendations."** Helps prevent opinions from being presented as facts.

When a teaching-style line belongs in the prompt, copy the quoted sentence and leave the explanation out of the prompt.

## Audience

One particularly useful technique is to specify your existing knowledge and desired level of depth.

For example, add this to your prompts:

> Assume I'm a product manager with deep, broad software engineering experience. Skip generic introductory explanations and focus on the concepts, underlying reasoning, trade-offs, and practical decisions. Draw analogies to software engineering where helpful, and use product-management terminology precisely.

This helps avoid overly elementary explanations while ensuring that unfamiliar concepts are properly introduced.
